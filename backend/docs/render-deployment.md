# Render deployment

## Option A: `render.yaml` (recommended)

This repo includes `backend/render.yaml`, a Render "Blueprint" spec.

1. Push this branch/repo to GitHub.
2. In the Render dashboard, choose **New > Blueprint** and point it at the repo.
3. Render reads `backend/render.yaml` and creates a `campus-exchange-api` web service with:
   - `rootDir: backend`
   - Build: `pip install -r requirements.txt`
   - Start: `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - Health check: `GET /health`
4. Fill in the env vars Render prompts for (marked `sync: false` in `render.yaml`, so they're not
   committed to git):
   - `DATABASE_URL` — your Neon **pooled** connection string (see [neon-setup.md](neon-setup.md))
   - `CORS_ORIGINS` — comma-separated origins, including your Vercel frontend URL once you have one
   - `SECRET_KEY` is auto-generated by Render (`generateValue: true`); `COOKIE_SECURE` and
     `COOKIE_SAMESITE` are already set to `true` / `none` for production — required because the
     Vercel frontend and this backend are on different domains (see
     [environment-variables.md](environment-variables.md)).
5. Deploy. Render runs the start command on every deploy, so `alembic upgrade head` keeps the
   schema in sync automatically — no manual migration step.

## Option B: manual web service

If you'd rather configure it by hand instead of using the Blueprint:

- **Root directory**: `backend`
- **Runtime**: Python 3 (matches `runtime.txt`)
- **Build command**: `pip install -r requirements.txt`
- **Start command**: `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
- **Health check path**: `/health`
- Add the same env vars listed above manually in the service's Environment tab.

## After deploying

- Confirm `https://<your-service>.onrender.com/health` returns `{"status":"ok"}`.
- Add the Render URL itself to `CORS_ORIGINS` if the API ever needs to be called from a tool hosted
  on the same domain (not required for the frontend, which is a separate origin on Vercel).
- Update the frontend's `VITE_API_BASE_URL` to `https://<your-service>.onrender.com/api/v1` — see
  [vercel-deployment.md](vercel-deployment.md).
